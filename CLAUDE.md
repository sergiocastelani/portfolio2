# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static, single-page personal portfolio for Sérgio C Castelani Jr. There is no build step, package manager, linter, or test suite: just `index.html`, `index.css`, `hash-tools.js`, and `images/`. To preview it, open `index.html` directly in a browser or serve the folder with any static server (for example `npx serve .` or `python -m http.server`).

## Architecture

- **Bootstrap 5.3 and Bootstrap Icons come from the jsDelivr CDN** (linked in `<head>`). Layout and spacing use Bootstrap utility classes (`row`, `col-*`, `p-*`, `mt-*`, `card`, and so on). Keep custom CSS small.
- **Theming**: `index.css` sets the theme variables on `html`: `--my-primary` (green `#86af49`) is the fill, border and button color; `--my-primary-text` (`#4f6e24`) is the text green (at least 4.5:1 on white and on `--bs-gray-100`), used for links, `strong`, numbers, chips and icons next to text, because `#86af49` fails text contrast; `--my-secondary` is a hover accent (footer icons); `--main-nav-height` is the navbar height and the single source of the scroll offset. `index.css` overrides Bootstrap's `.btn-primary` and `.border-primary` with `!important` so they use the theme green, and a global `:focus-visible` rule draws a green focus ring instead of Bootstrap's blue glow. New accent styling must use these variables, never Bootstrap's default blue.
- **CSS organization**: base rules (`html` variables, `main`, `a`, `strong`, `#profile`, `#profile-img`, `.social-btn`) come first. Right after `.social-btn` comes the `/* Personal projects */` block (the project-card rules, the overlay focus state and `#more-projects-toggle`). After it, each other page area has one block headed by a comment, in this order: `/* Layout and navigation */`, `/* Footer */`, `/* About */`, `/* Expertise */`, `/* What I bring */`, `/* Experience timeline */`, `/* Professional highlights */`, `/* Education */`, `/* Hash tools */`; each holds that area's rules and its own media queries. All these blocks sit before `/* Bootstrap overrides */`; `/* responsiveness */` comes last. The one exception to "media queries live in their block" is the project-card 768px rule, which stays in `/* responsiveness */` (see the last bullet). Style a section only inside its own block, and add a new block before `/* Bootstrap overrides */` for a new area. Classes created for a section are used only inside that section. `/* Hash tools */` holds the styles applied by `hash-tools.js` commands across sections (`.skill-chip.skill-chip-highlight`: `--my-primary-text` background, white text, navbar `scroll-margin-top`), so its classes are the exception to the one-section rule for classes.
- **Navigation**: `<nav id="main-nav">` is a sticky Bootstrap navbar placed before `<main>`. Its brand links to `#profile` (full name from 576px up, initials "SCCJ" below) and its links go to `#about`, `#skills`, `#experience`, `#projects` and `#education` (not `#value`). Below 768px the links collapse behind a hamburger; the inline script right after `</nav>` closes the open menu before scrolling and does nothing if `window.bootstrap` is missing. Every `section[id]` has a `scroll-margin-top` based on `--main-nav-height`, so headings land below the navbar, and scrolling is smooth unless the user prefers reduced motion.
- **Page sections** (in order inside `<main>`): the hero `#profile` (gray `.row`; the page's only `h1`, the title as a non-heading `<p class="h3">`, a tagline, the photo `images/photo2.png` with `alt`, and LinkedIn/GitHub/Email buttons as inline SVGs with `aria-label`s); `#about` "About" (summary and four `.stat-tile` key numbers); `#skills` "Expertise" (five `.expertise-card`s and a grouped "Full toolbox" of chips); `#value` "What I bring" (four `.value-item` statements); `#experience` "Experience" (an `<ol class="timeline">` of six `.timeline-item` roles, newest first, each with a `.timeline-date` badge); `#projects` "Featured Work" (`#projects-professional`, then `#projects-personal`); `#education` "Education & Languages" (education and languages columns). The `<footer>` is the last child of `<main>`: small Bootstrap Icons links (LinkedIn, GitHub, Email) and the copyright line, whose `<span id="footer-year">` holds a static "2026" that the footer's inline script replaces with the current year.
- **Section pattern**: each content section is `<section id="X" class="page-section" aria-labelledby="X-heading">` with `<h2 id="X-heading" class="border-start border-5 border-primary ps-3 fw-bold mb-5">`. `.page-section` gives the vertical padding; `#skills`, `#experience` and `#education` also carry `.section-alt` (the `--bs-gray-100` band), so gray and white bands alternate below the gray hero. Headings go `h1` (hero only), `h2` (section), `h3` for the first level inside a section (subheadings, and card or item titles placed directly under the `h2`), `h4` for titles under an `h3`. Tech badges are `<span class="badge skill-chip">` (light green tint, `--my-primary-text` text), usually inside a `d-flex flex-wrap gap-2` wrapper. Icons are Bootstrap Icons 1.11.3 glyphs (`<i class="bi bi-…" aria-hidden="true">`) when they are decorative.
- **Featured Work cards**: `#projects-professional` holds proprietary work as `.highlight-card` cards (large icon, title, company, description, chips). The cards themselves are deliberately not interactive: no card-wide link, `onclick`, `tabindex`, hover effect or pointer cursor. A card may hold plain text links to public videos in a `<p class="small">` line under its description (the Audaces card does), opened with `target="_blank" rel="noopener"`. `#projects-personal` holds the personal demos as copy-pasted blocks inside `<div class="col-12 col-lg-6">`: three featured cards (2 + 1 on lg, one per row below), then the `#more-projects-toggle` button, then `#more-projects`, a Bootstrap `collapse` that starts closed and holds the other demos. To add a demo, copy an existing block into the featured row or into `#more-projects`. The left image is a `div.project-card-img` with `role="link"`, `tabindex="0"` and `aria-label="<Title> live demo"`; its screenshot is an inline `background-image: url(./images/projects/<name>.png)`, and an inline `onclick="window.open(url,'_blank')"` opens the live demo. Inside it, an `aria-hidden` `.project-img-overlay` shows a "View" button on hover and on keyboard focus. The right column holds the title (`h4.card-title.h5`), a description whose source links use `target="_blank" rel="noopener"`, and a `<small class="text-body-secondary">` line listing the tech stack, separated by ` | `. The inline script right after `#projects` opens the demo when Enter is pressed on a focused screenshot and switches the toggle label between "Show more projects" and "Show fewer projects". Screenshots inside the closed collapse are not downloaded until it opens. Project screenshots go in `images/projects/`.
- **Scripts**: the one JS file is `hash-tools.js` (see Hash tools), loaded with `defer` in `<head>` right after the Bootstrap bundle. All other scripts are inline: each inline `<script>` sits right after (or inside) the markup it serves: after `</nav>`, inside the `<footer>`, and after `#projects`. The Bootstrap bundle is loaded with `defer`, so scripts check for `window.bootstrap` at use time or rely only on Bootstrap's DOM events. Without JavaScript all content stays visible, except that the "More projects" list stays closed.
- **Hash tools**: `hash-tools.js` (project root) holds every hash tool in one IIFE that adds no globals and does not use `window.bootstrap`. It reads `location.hash` on load and on every `hashchange`; a hash starting with `#exec-` (any case) has the form `#exec-<name>[-<params>]`, where `<name>` is `[A-Za-z0-9]+` (case-insensitive, ending at the first `-`) and `<params>` is `encodeURIComponent(JSON.stringify(array))`, so later `-` stay in the params. The router validates the name, decodes and parses the params, requires an array, converts each element with `String()` (missing params give `[]`) and calls `commands[<lowercase name>](params)`. Other hashes are ignored, so anchors work as before. A bad link (invalid name, undecodable or non-JSON params, a non-array value, an unknown command, a command that throws) changes nothing on the page and logs one `console.warn` prefixed `[hash-tools]` through `warn()`. To add a command, write `commands.<name> = function (params) { … };` in the file's `// Commands` region; commands use `warn()` for their own warnings.
- Below 768px, the `/* responsiveness */` media query in `index.css` changes the project image's corner radius from left-side to top-side and gives it a minimum height.
